# 9. App launcher icons + Linux window icon

Date: 2026-08-14

## Status
Accepted

## Context
Nook shipped with Flutter's stock launcher icons: the default blue Flutter
"F" on Android/iOS/macOS/Windows and **no window icon at all** on Linux
(the runner's `my_application.cc` never called `gtk_window_set_icon_from_file`,
so window managers fell back to a generic glyph). Branding was inconsistent
across platforms and a premium distribution needs a recognizable mark on every
launcher, dock, titlebar, and alt-tab switcher.

The brand is a green "n" mark (plus "nook" wordmark) on a `#FBFBFB` paper
background.

## Decision

### One source of truth, generated everywhere
- `flutter_launcher_icons ^0.14.4` (config block at the bottom of
  `pubspec.yaml`) drives icon generation from two assets in `assets/icons/`:
  - `favicon_fg.png` — the transparent foreground (the "n" glyph), used for the
    Android adaptive foreground and sized to the safe zone.
  - `favicon_full.png` — the opaque full logo, used as the base for legacy
    Android mipmaps, iOS, macOS, and Windows.
- Android adaptive icon: transparent foreground over a `#FBFBFB` background
  (background is a color resource, `values/colors.xml`), with the default 16%
  foreground inset so the glyph survives any launcher mask (circle, squircle,
  teardrop). Legacy `mipmap-*` PNGs are regenerated for pre-API-26 devices.
- iOS/macOS `AppIcon.appiconset` and Windows `app_icon.ico` are regenerated by
  the same run.

### Linux gets a window icon too
`flutter_launcher_icons` has **no Linux support**, so the window icon is a
small manual step:
- `linux/runner/icon.png` (a copy of `favicon_full.png`) is installed into
  `bundle/data/icon.png` by an `install(FILES ...)` rule in `linux/CMakeLists.txt`
  (must live in the top-level file, not `runner/CMakeLists.txt`, because
  `INSTALL_BUNDLE_DATA_DIR` is only in scope there).
- `linux/runner/my_application.cc` computes
  `g_path_get_dirname(fl_dart_project_get_assets_path(project))` → `data/`,
  joins `icon.png`, and calls `gtk_window_set_icon_from_file` after window
  creation, warning (not failing) if the icon can't be loaded.

## Consequences
- A single `dart run flutter_launcher_icons` regenerates every platform icon
  from the two source assets; the generated files under
  `android/app/src/main/res/`, `ios/…/AppIcon.appiconset/`,
  `macos/…/AppIcon.appiconset/`, and `windows/runner/resources/` are checked in.
- The adaptive icon's `ic_launcher_background` color lives in
  `values/colors.xml`; the foreground lives in per-density `drawable-*/` PNGs
  (this is the tool's layout, not vector drawables).
- Linux remains manual: re-copy the icon to `linux/runner/icon.png` when the
  art changes — the CMake install rule and the C++ lookup path must stay in
  sync (see AGENTS.md).
- No pubspec asset declaration is needed for icon generation — the tool reads
  files from disk, so `assets/icons/` stays out of the app bundle.
